# FieldLink 사용 매뉴얼

[README](../README.md) · [기술 스택](TECH_STACK.md) · [네트워크·설정](NETWORKING.md)

## 1. 기기별 준비

| 기기 | 실행할 것 | 접속 주소 |
| --- | --- | --- |
| 서버 데스크톱 | Python 서버 + Chrome 또는 Edge | `http://localhost:3000` |
| 같은 PC의 다른 브라우저 | Chrome 또는 Edge | `http://localhost:3000` |
| 같은 공유기의 스마트폰·노트북·다른 PC | 브라우저 | `http://서버PC의내부IP:3000` |

서버는 한 PC에서 켭니다. 다른 기기에는 Python을 설치하지 않아도 됩니다. 다른 기기의 localhost는 그 기기 자신을 가리킵니다.

## 2. 서버 시작과 종료

Windows에 Python 3.11 이상을 설치하고 `python --version`으로 확인합니다. 저장소를 내려받아 `start.cmd`를 더블클릭합니다. 첫 실행에는 `.venv`와 aiohttp 의존성 설치가 끝날 때까지 기다립니다.

수동으로 실행하려면 프로젝트 폴더에서 다음 명령을 사용합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe server.py
```

Python 명령이 `py`인 환경에서는 `py -3 run.py`로 시작할 수도 있습니다. macOS·Linux에서는 `sh start.sh`를 사용하며 운영체제마다 가상환경을 새로 만듭니다. macOS·Linux 실기기 실행은 검증 범위에 포함하지 않았습니다.

실제 Chrome 또는 Edge 주소창에 `http://localhost:3000`을 입력합니다. HTML 파일을 직접 열지 말고 Python 서버 주소로 접속합니다. 서버는 실행한 터미널에서 `Ctrl+C`로 종료합니다.

## 3. 같은 PC에서 Chrome과 Edge로 시험하기

1. Chrome에서 localhost 주소를 엽니다.
2. 이름과 `현장 작업자` 역할 선택 → **새 지원 세션 만들기**를 누릅니다.
3. 위에 표시된 **10자리 방 코드**를 확인합니다.
4. **화면 공유** → 탭·창·전체 화면 선택 → 브라우저의 **공유**를 누릅니다.
5. Edge에서 같은 localhost 주소를 엽니다.
6. 이름과 `원격 전문가` 역할을 선택하고 같은 방 코드로 **참여하기**를 누릅니다.
7. 영상과 **P2P 직접 연결** 표시를 확인합니다.
8. Edge에서 채팅·포인터·그리기를 사용해 Chrome에도 표시되는지 확인합니다.

카메라가 있다면 **카메라 켜기**도 사용할 수 있습니다. 역할은 화면 표시용이며 권한 등급이 아닙니다. 방은 최대 2명입니다.

## 4. 데스크톱 화면을 스마트폰·노트북에서 보기

### 데스크톱에서

1. Chrome 또는 Edge에서 `http://localhost:3000`을 엽니다.
2. 이름 입력 → **새 지원 세션 만들기**를 누릅니다.
3. **10자리 방 코드**를 확인합니다.
4. **화면 공유**를 눌러 보여줄 화면을 선택하고 브라우저의 **공유**를 누릅니다.

### 수신할 스마트폰·노트북에서

1. 수신 기기를 서버 PC와 같은 공유기의 Wi-Fi 또는 LAN에 연결합니다.
2. 수신 기기의 WebRTC 지원 브라우저에서 `http://서버PC의내부IP:3000`을 엽니다.
3. 이름과 데스크톱의 방 코드를 입력하고 **참여하기**를 누릅니다.
4. 데스크톱 화면이 표시되는지 확인합니다.
5. 영상이 도착했지만 멈춰 있으면 **영상 재생**을 누릅니다.

IP를 찾는 방법은 [네트워크 안내](NETWORKING.md#서버-pc의-내부-ip-확인)에 있습니다. 수신 기기 주소에 localhost를 입력하지 않습니다.

### 목소리와 원격 지시

- 목소리: 데스크톱에서 **마이크 켜기**와 권한 허용 → 수신 기기에서 **소리 켜기**
- 포인터: **포인터** 선택 → 영상의 위치 터치
- 주석: **그리기** 선택 → 영상에서 터치 또는 드래그
- 지우기: 현재 영상의 주석을 양쪽에서 지움
- 채팅: 메시지 입력 또는 빠른 메시지 선택

화면 공유는 시스템 소리를 캡처하지 않습니다. 데스크톱 마이크 음성을 별도 전송합니다. 가까운 두 기기에서 소리를 동시에 재생할 때는 이어폰으로 에코를 줄일 수 있습니다.

HTTP 보기 모드는 수신 기기의 카메라·마이크 권한을 요청하지 않습니다. 스마트폰·노트북 등 다른 기기가 영상을 보내려면 [HTTPS 설정](NETWORKING.md#다른-기기에서-카메라와-마이크-보내기)과 브라우저 지원이 필요합니다.

## 5. 버튼과 상태

| 버튼·표시 | 의미 |
| --- | --- |
| 새 지원 세션 만들기 / 참여하기 | 새 방 코드 생성 / 받은 방 입장 |
| 화면 공유 / 공유 중지 | 선택한 화면 송신 / 중지 |
| 카메라 켜기 / 끄기 | 카메라 영상 송신 전환 |
| 마이크 켜기 / 끄기 | 마이크 송신·음소거 전환 |
| 내 화면 공유 | localhost 보기 모드에서 일반 모드로 전환하고 화면 선택창 열기 |
| 영상 대기 중 | 상대방의 공유 영상이 아직 없어 재생 대기 |
| 영상 재생 | 도착한 상대 영상을 사용자 터치로 재생 |
| 소리 켜기 / 끄기 | 받은 음성 재생·음소거 |
| 미리보기 | 양쪽이 영상을 보낼 때 내 화면·상대 화면 전환 |
| 캡처 | 현재 영상과 주석을 합성한 PNG 저장 |
| 연결 정보 | 실제 통계·ICE·신호·연결 이벤트 확인 |
| 연결 다시 시도 | ICE restart 또는 신호 재접속 시도 |
| 세션 진단 내려받기 | 상태·이벤트·통계를 JSON으로 저장 |
| 연결 종료 | 방 퇴장 및 해당 기기의 송신 트랙 해제 |

**P2P 직접 연결**과 **영상 공유 중**은 별도 상태입니다. 연결 후에도 송신자가 화면 공유나 카메라를 켜야 영상이 표시됩니다.

## 6. view=0 / view=1

기본 사용에서는 주소 뒤의 옵션을 생략합니다.

- localhost: 일반 모드. 화면·카메라·마이크 공유 가능
- 일반 HTTP 내부 IP: 보기 모드. 수신·채팅·포인터·주석 사용
- `?view=1`: localhost·HTTPS에서도 보기 모드를 명시적으로 선택
- `?view=0`: 일반 접속. 일반 HTTP 내부 IP의 캡처 제한은 그대로 적용

이 값은 앱의 UI 모드 옵션이며 방 코드와 별개입니다. `view=1`을 제거해도 브라우저 보안·권한 제한이 해제되지는 않습니다.

## 7. 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| localhost 접속 실패 | Python 서버 터미널, 설치 오류, 3000번 포트 사용 여부 |
| 수신 기기에서 페이지가 안 열림 | 서버 PC의 내부 IP, 같은 공유기, 게스트 Wi-Fi·기기 간 차단·방화벽 |
| 데스크톱에 영상 대기 중만 표시 | 서버 PC의 localhost로 접속하고 **화면 공유** 사용 |
| 방 코드를 찾을 수 없음 | 코드 확인. 서버 재시작·빈 방 만료 뒤에는 새 방 생성 |
| 방이 가득 참 | 최대 2명. 불필요한 같은 방 탭에서 연결 종료 |
| 연결됐지만 영상 없음 | 송신자의 공유 시작·중지 상태 및 보기 모드 여부 |
| 소리가 없음 | 송신 마이크 켜기, 수신 소리 켜기, OS 음량 |
| 캡처 권한 오류 | 서버 PC는 localhost, 다른 기기 송신은 신뢰되는 HTTPS와 지원 브라우저 |
| 직접 연결 실패 | 같은 LAN에서 먼저 시험. 연결 정보 → 연결 다시 시도. 일부 망은 TURN 없이 실패 가능 |
| 화면 변경이 반영되지 않음 | 새로고침. 데스크톱에서는 필요시 Ctrl+F5 |

포트를 바꾸려면 아래 명령을 사용하고 양쪽 접속 주소도 맞춥니다.

```powershell
.\start.cmd --port 3001
```

브라우저의 **연결 종료**는 세션을 끝내고, 터미널의 `Ctrl+C`는 서버를 끝냅니다. 서버 재시작 시 방은 사라집니다. 빈 방은 기본 5분 뒤 정리됩니다.
