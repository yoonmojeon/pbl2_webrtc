SYSTEM DESIGN / 1:1 PEER CONNECTION

연결은 서버가, 전송은 브라우저가.

현장 Chrome과 전문가 Edge를 WebRTC로 직접 연결합니다.
신호 서버는 연결 정보를 교환하고, 영상·음성·부가 데이터는 P2P 경로로 전달합니다.

① 시스템 구성

MediaStream

카메라·마이크·화면을 가져옵니다. 카메라가 없어도 화면 공유로 시작합니다.

RTCPeerConnection

ICE로 직접 경로를 찾고 브라우저 사이에 영상·음성을 전송합니다.

RTCDataChannel

채팅·포인터·주석·장치 상태를 P2P로 전달합니다.

② 연결부터 지원 종료까지

  1. 방 생성·입장
    현장 브라우저가 만든 10자리 코드로 전문가가 입장합니다. 서버는 최대 2명만 허용합니다.
  2. SDP Offer / Answer 교환
    코덱과 송수신 정보를 협상합니다. 동시에 Offer가 발생하면 Perfect Negotiation으로 처리합니다.
  3. ICE 후보 교환·경로 탐색
    host·STUN 후보로 직접 연결 가능한 경로를 확인합니다. TURN과 SFU는 사용하지 않습니다.
  4. 미디어·데이터 직접 전송
    화면 선택은 사용자 클릭으로 시작합니다. 영상 소스를 교체해도 채팅과 연결을 유지합니다.
  5. 현장 확인·주석·품질 측정
    정규화 좌표로 영상의 같은 위치를 가리키고, 실제 getStats 통계를 확인합니다.
  6. 종료·정리
    로컬 미디어 트랙과 PeerConnection을 종료합니다. 상대방은 재입장을 기다릴 수 있습니다.

③ 기술 선택과 설계 근거

선택이유고려사항
Python + aiohttp비동기 HTTP·WebSocket, SDP·ICE 교환과 Room 관리방 상태는 단일 서버 메모리
1:1 P2P + STUN미디어 서버 없이 직접 전송대칭 NAT·UDP 차단 시 실패 가능
replaceTrack카메라↔화면 전환 시 세션 유지한 참여자당 영상 소스 1개
정규화 좌표영상 표시 크기와 관계없이 위치 일치영상 검은 여백 제외·소스별 주석 분리
getStats + 송신 상한실제 품질 관찰과 전송량 조절RTT는 영상 전체 지연과 다름
ICE restart·재접속일시적 경로·신호 장애 복구방 소멸·차단된 망의 성공 보장 없음
같은 공유기에서는 데스크톱의 localhost 화면 공유를 다른 기기의 HTTP 보기 모드로 수신할 수 있습니다. 다른 기기의 카메라·마이크 송신에는 신뢰되는 HTTPS가 필요합니다. 기본 구성은 직접 P2P 전용이며, 일부 NAT·회사망에서는 연결할 수 없습니다. 역할은 화면 표시용이며 별도 로그인 인증은 없습니다.
